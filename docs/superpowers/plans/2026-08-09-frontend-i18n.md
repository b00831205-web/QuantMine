# Frontend i18n Completion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move every user-visible Chinese frontend literal into complete English, Chinese, and French i18next resources, follow the browser language on first visit, and fall back to English for unsupported locales.

**Architecture:** Keep the existing `react-i18next` integration and use three bundled JSON resources. Components translate at render time with feature-scoped keys; presentation utilities accept a translator or return stable translation keys. Detection uses query string, saved choice, then browser language, with English as the fallback.

**Tech Stack:** React 18, TypeScript 5.6, Vite 5, Vitest, Testing Library, i18next 26, react-i18next 17, i18next-browser-languagedetector 8.

## Global Constraints

- Only user-visible strings are localized; comments, API fields, route paths, symbols, model names, and backend domain data remain unchanged.
- Supported language families are exactly `en`, `zh`, and `fr`; regional variants resolve to their base language and unsupported languages fall back to `en`.
- Locale files are UTF-8 JSON and have identical recursive key sets.
- Existing user modifications in the dirty worktree must be preserved. Do not stage or commit pre-existing changes; use file-level review checkpoints instead of task commits where edits overlap them.
- English copy is the canonical fallback. Chinese copy must preserve current product meaning without mojibake.
- French copy uses idiomatic product and quantitative-finance terminology; API, PDF, SQL, AI, ticker symbols, model IDs, and run IDs remain unchanged.
- Interpolation and pluralization use i18next syntax; do not concatenate translated fragments.

## File Map

- `frontend/src/i18n/index.ts`: production language configuration and detector precedence.
- `frontend/src/i18n/locales/en.json`: complete canonical English resource.
- `frontend/src/i18n/locales/zh.json`: complete Chinese mirror of the English keys.
- `frontend/src/i18n/locales/fr.json`: complete idiomatic French mirror of the English keys.
- `frontend/src/i18n/index.test.ts`: language resolution tests.
- `frontend/src/i18n/locales.test.ts`: locale JSON validity and recursive key parity.
- `frontend/src/test/setup.ts`: deterministic English test default; individual locale tests opt into Chinese.
- `frontend/src/utils/workflowStatus.ts`: stable workflow state-to-translation-key mapping.
- `frontend/src/components/**`: shared, layout, chart, authentication, and AI component translation consumers.
- `frontend/src/pages/**`: page-level translation consumers.

- [ ] **Step 1: Write locale parity characterization tests**

Create `locales.test.ts` with a recursive leaf-key collector and literal expectations:

```ts
import en from './locales/en.json';
import zh from './locales/zh.json';
import fr from './locales/fr.json';

const leafKeys = (value: unknown, prefix = ''): string[] => {
  if (typeof value !== 'object' || value === null) return [prefix];
  return Object.entries(value).flatMap(([key, child]) =>
    leafKeys(child, prefix ? `${prefix}.${key}` : key),
  );
};

describe('locale resources', () => {
  it('keeps the English, Chinese, and French key sets identical', () => {
    expect(leafKeys(zh).sort()).toEqual(leafKeys(en).sort());
    expect(leafKeys(fr).sort()).toEqual(leafKeys(en).sort());
  });

  it('contains no replacement characters caused by broken encoding', () => {
    expect(JSON.stringify(en)).not.toContain('\uFFFD');
    expect(JSON.stringify(zh)).not.toContain('\uFFFD');
    expect(JSON.stringify(fr)).not.toContain('\uFFFD');
  });
});
```

In `index.test.ts`, reset modules and storage before each case, replace `navigator.language`/`navigator.languages`, dynamically import `./index`, and assert these literal outcomes:

```ts
it.each([
  { browser: 'zh-CN', expected: 'zh' },
  { browser: 'en-US', expected: 'en' },
  { browser: 'fr-FR', expected: 'fr' },
  { browser: 'de-DE', expected: 'en' },
])('resolves $browser to $expected on first visit', async ({ browser, expected }) => {
  localStorage.clear();
  Object.defineProperty(window.navigator, 'language', { configurable: true, value: browser });
  Object.defineProperty(window.navigator, 'languages', { configurable: true, value: [browser] });
  vi.resetModules();
  const { default: instance } = await import('./index');
  await vi.waitFor(() => expect(instance.isInitialized).toBe(true));
  expect(instance.resolvedLanguage).toBe(expected);
});

it('prefers a saved supported language over the browser language', async () => {
  localStorage.setItem('i18nextLng', 'en');
  Object.defineProperty(window.navigator, 'language', { configurable: true, value: 'zh-CN' });
  vi.resetModules();
  const { default: instance } = await import('./index');
  await vi.waitFor(() => expect(instance.isInitialized).toBe(true));
  expect(instance.resolvedLanguage).toBe('en');
});
```
